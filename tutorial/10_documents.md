# 10. 文書處理：計劃書、簡報、論文

> 本章適用全實驗室。
>
> 這章跟 `instructions.md` 的第二條禁令是同一件事：**不得自行產生假資料。**
> 在程式那邊，違規長成「找不到檔案就用隨機數」；在文書這邊，長成
> 「編一個看起來很合理的參考文獻」。同一個問題，換一張臉。

---

## 一、AI 沒有你的資料

這是整章唯一真正重要的一句話。

Claude 不知道你的實驗結果、不知道你的試件編號、沒讀過你指導教授上週給的意見、
也沒看過你那台儀器的規格。你不給，它就**沒有**。

問題在於它不會空白，**它會填**。而且填得很像真的。

### 三種最常見的幻覺

| 類型 | 長什麼樣 | 為什麼危險 |
|---|---|---|
| **數字** | 「本研究結果顯示成功率達 87%」 | 你根本沒算過 87%，但這句話很順，你會滑過去 |
| **圖表** | 生一張漂亮的趨勢示意圖 | 那是它畫的示意圖，不是你的量測結果 |
| **參考文獻** | 完整的作者、期刊、年份、DOI | **最致命的一種**，見下 |

### 為什麼假的參考文獻特別致命

AI 編出來的引用通常長這樣：

```
Chen, Y., & Wang, L. (2019). Modal identification of steel frame
structures under ambient excitation. Journal of Sound and Vibration,
442, 112–128. https://doi.org/10.1016/j.jsv.2018.11.023
```

作者是真的存在的研究者，期刊是真的，卷期格式對，DOI 格式也對 ——
**但這篇論文不存在。**

它之所以危險，是因為它通過了你所有的直覺檢查。你不會懷疑它，因為它看起來比你自己手打的還整齊。
等到審稿人或口試委員去查，那才是真的出事。

> **鐵則：任何一條你沒有親自打開來看過的引用，都不要放進文件裡。**

## 二、先餵資料，再要求產出

正確的順序永遠是：**你準備材料 → AI 組織與表達**。
不是「AI 生一份出來 → 你再去找資料補」。

### 動手前先準備好

| 材料 | 從哪來 | 沒有的話 |
|---|---|---|
| 數據與結果 | `results/tables/`、`results/figures/` | 先跑完分析，見 [`03_first_task.md`](03_first_task.md) |
| 圖表 | `results/figures/`（300 dpi、座標軸有單位） | 不要讓 AI 畫示意圖代替 |
| 參考文獻 | 你自己的 `.bib` / EndNote 匯出 / 文獻清單 | 自己去查，這步沒有捷徑 |
| 規格與參數 | `SPEC.md` | 不要口頭複述，直接給檔案 |
| 格式要求 | 補助單位的格式規定、期刊 author guidelines、系上論文格式 | 去官網下載 |
| 前一版 | 上一版的計劃書、指導教授的修改意見 | 有就一定要給 |

### 圖表：只能來自你的分析

論文和計劃書裡的圖，**唯一合法的來源是 `results/figures/`** —— 也就是由
可重跑的腳本產生、通過物理合理性檢查的那些圖。

AI 可以幫你做的是：

- ✅ 調整圖的標籤、單位標示、字級、配色
- ✅ 寫圖說（caption）
- ✅ 建議「這組資料用哪種圖比較清楚」
- ✅ 幫你改繪圖腳本，重新產生一張

不能做的是：

- ❌ 直接生一張「示意圖」放進結果章節
- ❌ 從你貼的數字「推測」趨勢畫出來

**概念示意圖**（流程圖、實驗配置圖、座標系定義圖）是例外 —— 那本來就不是量測結果，
可以讓 AI 幫忙畫。但要標清楚它是示意圖。

### 參考文獻：給清單，並限制範圍

```
以下是我的參考文獻清單（附 refs.bib）。
撰寫時只能引用這份清單裡的文獻。
如果你認為某個論點需要引用，但清單裡沒有合適的，
不要自己補一篇 —— 標記 [需補引用] 並告訴我需要什麼樣的文獻。
```

最後那句是關鍵。給它一個「不知道」的合法出口，它就不會用編造來填。

## 三、Prompt 要說清楚的六件事

多數失敗不是 AI 不會寫，是**你沒說清楚要什麼**。下面六項缺一項，就會多來回一輪。

### 1. 長度與格式

**用字數，不要只用頁數。** AI 抓不準頁數 —— 頁數取決於字級、行距、圖的大小、模板邊界，
這些它看不到。

| 你想要 | 這樣講 |
|---|---|
| 計劃書某節 | 「約 1200 字，三段」 |
| 簡報 | 「12 張，每張 bullet 不超過 5 點、每點不超過 20 字」 |
| 論文章節 | 「約 2500 字，含 2 張圖、1 張表」 |
| 摘要 | 「250 字以內，單段，不分小標」 |

如果真的有頁數限制（很多計劃書有），講清楚換算基準：
「A4、12pt、單行間距，這樣大約每頁 900 字，總共不能超過 5 頁 → 目標 4000 字左右」。

### 2. 可以用哪些資料

明確到檔案路徑，不要只說「用我的實驗結果」：

```
可以使用：
- results/tables/2026-09-02_S03_natural_freq.csv
- results/figures/2026-09-02_S03_fft.png
- SPEC.md 第一節（單位）與第三節（感測器）
- refs.bib

不在這份清單裡的數字、圖、文獻，一律不要出現。
```

### 3. 哪些可以改、哪些不能動

這條最常被忘記，也最常造成災難 —— 你只想改第三章，結果整份被重寫，
指導教授上週改的地方全沒了。

```
可以改：第 3 章「研究方法」全部
不要動：
- 第 1、2 章（指導教授已經審過）
- 所有章節編號與圖表編號
- 參考文獻格式（已依期刊規定調整過）
- 附錄
```

改既有文件之前，**先 commit 一次或另存一份**。這樣改壞了隨時回得去
（見 [`06_git_basics.md`](06_git_basics.md)）。

### 4. 語氣與場合

不同文件的語氣差很多，不指定就會拿到一種平均值 —— 哪邊都不太對。

| 文件 | 語氣 | 例子 |
|---|---|---|
| 計劃書 | 正式、具說服力、強調價值與可行性 | 「本計劃將建立…，可望解決…之問題」 |
| 期刊論文 | 客觀、精確、被動語態、不誇大 | 「量測結果顯示一階固有頻率為 12.1 Hz」 |
| 研討會簡報 | 口語、短句、重點導向 | 「三次量測差異小於 1%」 |
| 進度報告 | 直述、誠實、含問題與風險 | 「校正係數尚未取得，此部分延後」 |

講法：

```
語氣：投稿國際期刊的正式學術英文，客觀、精確，不使用誇大措辭
（如 novel、significant improvement）。避免第一人稱。
數值一律附單位，依 SPEC.md 的單位系統。
```

### 5. 讀者是誰

同樣的內容，寫給不同人要換說法：

- **審查委員（跨領域）** → 專有名詞要解釋，強調意義
- **同領域期刊審稿人** → 可以直接用術語，重點在方法嚴謹度
- **系上口試委員** → 熟悉你的題目，重點在你自己做了什麼
- **廠商 / 業界** → 少公式，多應用價值

### 6. 不確定就停下來問

這條是 `instructions.md` 的第五條，在文書工作上一樣適用，而且更要強調：

```
如果你需要的資訊我沒有提供 —— 缺數據、缺文獻、不確定我要哪種語氣、
不確定某個章節能不能動 —— 停下來問我，不要自己假設。
寧可多問一輪，也不要生出我要花時間去查證的內容。
```

### 完整的 prompt 範本

```
【任務】
撰寫計劃書第三章「研究方法」。

【格式】
約 1200 字，分三小節。A4、12pt。使用繁體中文。

【可用資料】
- SPEC.md（單位、座標系、感測器規格）
- results/figures/2026-09-02_S03_fft.png
- results/tables/2026-09-02_S03_natural_freq.csv
- refs.bib（參考文獻清單）
清單以外的數字、圖、文獻一律不要出現。

【修改範圍】
只寫第三章。不要動其他章節、章節編號、圖表編號。

【語氣】
國科會計劃書的正式書面語，強調方法的可行性與嚴謹度，不誇大。
數值一律附單位。

【讀者】
跨領域審查委員，非本領域專家。專有名詞第一次出現時簡短說明。

【規則】
- 需要引用但 refs.bib 裡沒有合適文獻時，標記 [需補引用] 並說明需要什麼，不要自己補
- 需要數據但我沒給的，標記 [需補數據]，不要估算
- 任何不確定的地方，停下來問我
```

看起來很長，但這份 prompt 你只要寫一次，之後每一章都能重用，只改【任務】和【可用資料】。

## 四、三種文件的重點差異

| | 計劃書 | 簡報 | 論文 |
|---|---|---|---|
| 讀者要什麼 | 「這值得投資嗎」 | 「重點是什麼」 | 「這個結論可信嗎」 |
| 最重要的 | 可行性、預期成果 | 一頁一個訊息 | 方法可重現、數據充分 |
| AI 最會犯的錯 | 講得太空泛、形容詞太多 | 一張塞太多字 | 編引用、過度宣稱 |
| 你要特別檢查 | 有沒有具體的量化目標 | 圖有沒有大到看得清 | 每一條引用、每一個數字 |

### 簡報的額外提醒

AI 產出的投影片文字幾乎一定太多。給它硬性限制：

```
每張投影片：標題一行 + 最多 5 個 bullet，每個 bullet 不超過 20 字。
講稿另外寫在備註欄，不要放在投影片上。
```

另外，**簡報的圖比字重要**。與其讓 AI 寫滿文字，不如叫它告訴你「這頁該放哪張圖」，
然後你從 `results/figures/` 拿真的圖放上去。

### 論文的額外提醒

- 數字要跟 `results/tables/` 對得起來，**逐一對照**，不要相信「應該沒問題」
- 單位要跟 `SPEC.md` 一致（見 [`04_verification.md`](04_verification.md)）
- 圖說（caption）要能獨立看懂，不依賴內文
- **投稿前確認該期刊與學校對 AI 使用的揭露規定** —— 各家不同，且會變，去官網看最新版

## 五、可以直接產生檔案

Claude 可以直接輸出 `.docx`、`.pptx`、`.xlsx`、`.pdf`，不用你自己複製貼上排版。
但**規則完全一樣** —— 它只是換了輸出格式，不會因此就有了你的資料。

實務上的建議：

- 先把內容用純文字或 Markdown 確認過，再叫它產生 `.docx` / `.pptx`
- 有現成模板（系上論文格式、實驗室簡報 template）就把模板一起給它
- 產生後**一定要自己打開看過**，尤其是圖有沒有跑位、表格有沒有斷行

## 六、交出去之前的檢查清單

跟 [`04_verification.md`](04_verification.md) 的物理合理性檢查是同一個精神：
**AI 產出的東西，你要能自己驗證。**

- [ ] **每一條參考文獻我都親自打開看過**（不是看 DOI 格式對不對，是真的開啟過）
- [ ] 每個數字都能在 `results/` 裡找到出處
- [ ] 每張圖都是分析腳本產生的，不是 AI 畫的
- [ ] 單位與 `SPEC.md` 一致
- [ ] 沒有我看不懂的句子（看不懂就是還沒讀完，不是寫得高深）
- [ ] 沒有我無法回答的宣稱（口試時被問到答不出來的，就不要寫）
- [ ] 圖表編號與內文引用對得起來
- [ ] 長度符合規定
- [ ] 該揭露 AI 使用的地方有揭露

> 最後兩項是形式，前面幾項是責任。**文件掛的是你的名字，不是 Claude 的。**

## 七、常見失敗

| 徵兆 | 原因 | 怎麼處理 |
|---|---|---|
| 引用查不到 | 沒給文獻清單，或沒限制範圍 | 給 `.bib`，並明講「只能用清單裡的」 |
| 出現沒看過的數字 | 沒給資料就叫它寫結果 | 退回，要求標記 `[需補數據]` 而不是估算 |
| 整份被重寫 | 沒講哪些不能動 | 先 commit，再明確列出禁改範圍 |
| 語氣像行銷文案 | 沒指定語氣與讀者 | 指定文件類型與讀者，並禁用誇大詞 |
| 頁數永遠對不上 | 用頁數當指標 | 改用字數，並給換算基準 |
| 內容很順但很空 | 材料不夠，它只好講通則 | 補資料，不是換 prompt |

最後一條值得單獨說：**當 AI 寫出來的東西「很順但沒有內容」，通常不是它的問題，是你給的材料不夠。**
這時候要回去補資料，不是換個講法再叫它寫一次 —— 換十次講法，材料不變，結果不會變。
