# 3. 第一個任務：三階段流程

用一個具體例子走完整套流程：**從 S03 試件的三組量測資料算出前三階固有頻率**。

三個階段之間都要停下來等你確認。這不是禮貌，是控制點。

---

## 階段 1：規劃

### 你怎麼開場

```
請依 instructions.md 的流程，為以下任務建立 PLAN：
從 data/raw/20260902_S03_*.csv 三組資料算出前三階固有頻率，
並與有限元模型的 12.4 / 78.1 / 219 Hz 比對。
```

### Agent 應該先問你三個問題

`instructions.md` 要求規劃前先提出三個關鍵問題。合理的問題長這樣：

- 「三組資料是重複量測還是不同工況？要平均還是分別算？」
- 「有限元模型的邊界條件是固支還是簡支？影響能不能直接比對」
- 「`SPEC.md` 裡 LC-1 的校正係數還是空的，這個任務需要力訊號嗎？」

**如果 agent 沒問就直接開始寫 PLAN，把它叫回來。** 沒有問題通常代表它在用預設假設填空。

### PLAN 該有什麼

照 `plans/PLAN_template.md`，存成 `plans/2026-09-02_S03_modal.md`。重點在兩節：

**步驟拆解 —— 每一步都要有驗收標準。**「計算 FFT」不是步驟，「計算 FFT，且總能量與時域一致（Parseval 誤差 < 1%）」才是。

**「不做什麼」—— 這節最常被跳過，也最重要。** 明確寫「不做阻尼比估算」「不修改有限元模型」，agent 就不會自己擴張範圍。

### 這個階段不准出現程式碼

一行都不行。你要在還能便宜地改變主意的時候討論方法，而不是看著 200 行 code 說「其實我想的不是這樣」。

---

## 階段 2：執行

你確認 PLAN 之後才開始。

**一次只做一步，做完停下來回報。** PLAN 有五步就回報五次。

覺得慢是正常的。但第 2 步濾波參數選錯，你會在第 2 步就看到濾波前後對照圖並抓出來，而不是在第 5 步看到一張莫名其妙的頻譜圖，再回頭找是哪裡出問題。

### 檔案放哪

- 一次性腳本 → `scripts/2026-09-02_modal_analysis.py`
- 會重複用的函式（讀檔、單位轉換、濾波）→ `src/`
- 中間資料 → `data/processed/`，檔名要看得出來源與處理方式

一個任務改超過三個檔案，agent 要先說明再動手。

---

## 階段 3：驗證與產出

### 三件事，缺一不可

1. **圖或表** → `results/figures/2026-09-02_S03_fft.png`（300 dpi，座標軸標物理量與單位）
2. **一段文字說明結果代表什麼** —— 不是「FFT 完成」，是「一階 12.1 Hz，比 FE 模型低 2.4%，三次量測差異 0.8%，一致性良好」
3. **可以重跑的腳本** —— 你關掉對話、明天重跑，要能得到同一張圖

### 物理合理性檢查

逐條檢查並在回報中列出結果，不能只說「已檢查」。詳見 [`04_verification.md`](04_verification.md)。

### 補 DEVLOG

任務結束在 `DEVLOG.md` **最後面** append 一筆：做了什麼、為什麼這樣做、結果、下一步。

只往後加，不修改舊紀錄。半年後你想知道「當初為什麼選 500 Hz 截止頻率」，答案在這裡。

---

## 常見的走鐘與怎麼拉回來

| 徵兆 | 怎麼處理 |
|---|---|
| 沒問問題就寫 PLAN | 「請先提出三個關鍵問題」 |
| PLAN 階段開始寫 code | 「規劃階段不寫程式碼，請回到 PLAN」 |
| 一次做完五個步驟 | 「一次只做一步，請回報第 1 步結果」 |
| 找不到檔案就用範例資料 | 停下來查為什麼找不到。這是硬性禁止事項 |
| 回報只說「已完成」 | 「請依 instructions.md 第八節的五點格式回報」 |
